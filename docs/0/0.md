# Career OS — MVP

**Status:** Draft  
**Product:** Personal Career Operating System  
**Primary User:** Vishay  
**Platform:** Google Antigravity  
**Goal:** Increase the user's access to high-paying foreign AI/ML opportunities by automating opportunity discovery, network management, and daily prioritization while keeping the user in control of all external actions.

---

## 1. Product Vision

Build a lightweight agentic career system that runs every morning and answers one question:

> **"Given everything happening in my job search and network, what are the highest-value actions I should take today?"**

The system should:

1. Discover relevant opportunities.
2. Identify and manage relevant networking actions.
3. Combine these signals.
4. Prioritize the user's limited time.
5. Produce a concise daily action plan.
6. Let the user execute the actions.
7. Feed the outcomes back into the system.

The product is intentionally minimal. It should optimize for **career leverage, not automation complexity**.

# 3. Goals

### Primary Goals

- Find high-value foreign AI/ML opportunities.
- Identify people worth contacting for those opportunities.
- Maintain useful relationship context automatically.
- Reduce time spent searching, tracking and deciding.
- Increase the number of high-quality conversations and opportunities.
- Help the user consistently execute the highest-leverage career actions.

### Secondary Goals

- Maintain a lightweight history of applications and relationships.
- Avoid missed follow-ups.
- Learn from recruiter/network responses.
- Eventually improve recommendations based on outcomes.

---

# 4. Non-Goals

The MVP will **not**:

- Automatically send LinkedIn messages.
- Automatically send emails.
- Automatically submit job applications.
- Automatically connect with people on LinkedIn.
- Build a large CRM.
- Build a web dashboard.
- Build a vector database.
- Build complex multi-agent infrastructure.
- Automatically make career decisions for the user.
- Optimize for application volume.

The system recommends and prepares actions; **the user executes consequential external actions.**

---

# 5. Users

### Primary User

An experienced AI/ML engineer/scientist seeking:

- Foreign opportunities.
- High compensation.
- Stronger companies/teams.
- AI/ML systems and applied AI roles.
- Long-term career acceleration.

The system should be personalized around the user's career profile rather than being a generic job-search assistant.

# 6. System Components

The MVP contains exactly three agents.

## 6.1 Opportunity Scout

### Purpose

Find new opportunities that are genuinely relevant to the user's career goals.

### Trigger

Runs automatically every morning.

### Inputs

- `career/profile.md`
- `career/target_roles.md`
- `career/target_geographies.md`
- Existing opportunities
- Publicly available job/company information

### Responsibilities

1. Search for relevant job opportunities.
2. Filter out obviously irrelevant roles.
3. Identify new opportunities.
4. Remove duplicates.
5. Gather basic information:
   - Company
   - Role
   - Location
   - Remote/onsite
   - Seniority
   - Compensation when available
   - Visa/sponsorship information when available
   - Job URL
   - Posting date when available
6. Assess relevance to the user's profile.
7. Identify opportunities that deserve further attention.

### Output

A small list of high-value opportunities.

Target:

**3–5 opportunities/day maximum.**

Example:

```text
Company: X
Role: Staff AI Scientist
Location: US
Fit: Strong
Visa: Sponsorship appears possible
Why relevant: Strong overlap with speech/AI systems
Network opportunity: High
URL: ...
```

---

# 7. Network Manager

### Purpose

Determine who the user should build or maintain relationships with.

### Trigger

Runs automatically every morning.

### Inputs

- People database
- Previous interactions
- New opportunities
- Existing applications
- Publicly available information

### Responsibilities

1. Identify relevant people associated with important opportunities.
2. Identify:
   - Recruiters
   - Hiring managers
   - Team leads
   - Relevant engineers/scientists
   - Existing connections
3. Identify potential warm paths.
4. Review previous conversations.
5. Detect overdue follow-ups.
6. Determine appropriate next actions.
7. Generate message drafts when appropriate.
8. Maintain relationship state.

### Relationship information

Each person should minimally contain:

```text
name
company
role
profile/contact URL
relationship status
last contact
conversation summary
next step
follow-up date
associated opportunity
```

The supplied networking workflow similarly uses contact information, last-contact date, relationship status, conversation summary, next steps and follow-up date as the core tracking model.

### Output

```text
PERSON
Why this person matters
Previous context
Recommended action
Draft message
Follow-up date
```

---

# 8. Career Prioritizer

### Purpose

Act as the final decision-support layer.

It combines the output of the Opportunity Scout and Network Manager and determines what deserves the user's time.

### Trigger

Runs after the morning scouts finish.

### Inputs

- New opportunities
- Networking actions
- Active applications
- Interviews
- Recruiter conversations
- Follow-ups
- Career profile
- Previous outcomes

### Responsibilities

1. Rank actions by career leverage.
2. Remove low-value activities.
3. Combine related actions.
4. Identify urgent actions.
5. Identify high-upside actions.
6. Produce the user's daily action plan.
7. Explain why each action matters.

### Output

**Maximum 3–5 actions.**

Example:

```text
TODAY'S CAREER PRIORITIES

1. Reply to Recruiter X
   Why: Strong role fit + recruiter already engaged.
   Time: 10 min
   Draft: ...

2. Contact Engineer Y
   Why: Relevant team at target company.
   Time: 15 min
   Draft: ...

3. Prepare for Company Z interview
   Why: Interview scheduled this week.
   Time: 60 min
   Focus: ...

SKIP TODAY
7 generic job postings discovered.
Low leverage relative to the actions above.
```

# 11. Minimal Data Model

## People (`data/people.csv`)

| Field | Type | Description |
|---|---|---|
| id | String (PK) | Deterministic ID (e.g. `per_001`) |
| name | String | Contact full name |
| company | String | Current company |
| role | String | Current role |
| url | String | Public profile/contact URL (e.g. LinkedIn) |
| relationship_status | Enum | `cold` / `aware` / `warm` / `engaged` / `advocate` |
| last_contact_date | Date | YYYY-MM-DD of last interaction |
| next_follow_up_date | Date | YYYY-MM-DD of next planned outreach |
| conversation_summary | String | RFC 4180 quoted summary of recent context |
| next_step | String | Recommended outreach action |
| opportunity_id | String (FK) | Associated `opp_xxx` identifier if role-linked |
| notes | String | Additional context and mutual connections |

## Opportunities (`data/opportunities.csv`)

| Field | Type | Description |
|---|---|---|
| id | String (PK) | Deterministic ID (e.g. `opp_001`) |
| company | String | Company name |
| role | String | Position title |
| level | String | Senior / Staff / Principal / Lead |
| team | String | Team or research group (e.g. Speech & Inference) |
| location | String | Country / City (Global search universe) |
| remote_policy | Enum | `Remote` / `Hybrid` / `Onsite` |
| visa_sponsorship | Enum | `Yes` / `Likely` / `Unknown` / `No` |
| relocation_support | Enum | `Yes` / `Likely` / `Unknown` / `No` |
| compensation | String | Salary range / total compensation |
| posting_date | Date | YYYY-MM-DD posting or discovery date |
| url | String | Job URL / ATS link |
| fit_category | String | `Speech / Voice / Audio`, `AI Infrastructure / Inference`, `Foundation Models`, etc. |
| fit_score | Enum | `Strong` / `Moderate` / `Low` |
| why_relevant | String | Why Vishay's ASR + ML systems background provides an advantage |
| stretch_skills | String | Missing skills or stretch requirements |
| status | Enum | `discovered` / `considering` / `applied` / `screening` / `technical` / `offer` / `rejected` / `archived` |
| date_applied | Date | YYYY-MM-DD when applied (empty if not applied) |
| primary_contact_id | String (FK) | Associated `per_xxx` (recruiter, hiring manager, or referrer) |
| network_status | Enum | `None` / `Identified` / `Contacted` / `In-Conversation` / `Referred` |
| notes | String | Key context, team details, and strategic alignment |

# 12. Scheduling

### Morning

Run:

```text
Opportunity Scout
       ↓
Network Manager
       ↓
Career Prioritizer
       ↓
Daily Career Brief
```

The exact time should be configurable.

### Future iterations

Potential additional triggers:

- New recruiter email.
- Interview scheduled.
- Follow-up date reached.
- Application status changes.

These are **not required for MVP**.

---

# 13. Human-in-the-Loop Policy

The system may:

### Automatically

- Research.
- Analyze.
- Classify.
- Track.
- Deduplicate.
- Summarize.
- Generate drafts.
- Recommend actions.
- Update internal state.

### Require user approval

- Sending messages.
- Sending emails.
- Applying to jobs.
- Connecting with people.
- Sharing personal information.
- Any consequential external action.

This keeps the system useful without turning the user's professional identity into an uncontrolled automation.

---

# 14. Prioritization Principles

The Career Prioritizer should optimize for:

1. **Career upside**
2. **Role fit**
3. **Probability of meaningful traction**
4. **Network leverage**
5. **Compensation potential**
6. **Geographic/visa fit**
7. **Strategic career value**
8. **Time required**

The system should prefer:

> **One high-value relationship or opportunity over ten low-value applications.**

It should explicitly tell the user when something is **not worth doing**.

---

# 15. Success Metrics

The MVP should not optimize for the number of jobs found.

Track:

### Leading indicators

- Relevant opportunities discovered.
- Relevant people identified.
- Meaningful conversations started.
- Follow-ups completed.
- Referrals generated.
- Interviews generated.

### Outcome indicators

- Recruiter responses.
- Referral conversion.
- Interview conversion.
- Offers.
- Compensation improvement.
- International opportunities generated.

### System metric

**User execution rate:**

> Percentage of recommended high-priority actions actually completed.

The system is successful if it causes the user to spend more of their limited time on high-value career activities.

---

# 16. MVP Acceptance Criteria

The MVP is complete when:

- [ ] Career profile can be stored and read by all agents.
- [ ] Opportunity Scout runs automatically every morning.
- [ ] Opportunity Scout produces ≤5 relevant opportunities.
- [ ] Network Manager runs after Opportunity Scout.
- [ ] Network Manager identifies relevant people/actions for important opportunities.
- [ ] Existing relationship information is maintained.
- [ ] Follow-ups are surfaced.
- [ ] Career Prioritizer consumes both outputs.
- [ ] Career Prioritizer produces ≤5 actionable recommendations.
- [ ] Each recommendation explains why it matters.
- [ ] Message drafts can be generated.
- [ ] No external communication happens without user approval.
- [ ] Daily report is generated automatically.
- [ ] User actions can be fed back into the system.
- [ ] The entire workflow can run with simple Markdown/CSV state.

---

# 17. MVP Principle

**Do not build more until this loop works:**

```text
DISCOVER
   ↓
UNDERSTAND
   ↓
PRIORITIZE
   ↓
ACT
   ↓
LEARN
   ↓
REPEAT
```

The product's purpose is not to build an impressive agentic system.

Its purpose is to make the user's **career actions higher leverage every day.**

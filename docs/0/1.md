I want to add a **Progressive Interviews** feature to my Career OS.

Before writing code, inspect the existing Career OS architecture, data model, UI, and workflows so this fits naturally into what already exists.

### Product idea

I don't want interviewing to be random.

I want Career OS to help me deliberately progress through interviews:

**easy / low-stakes interviews → moderate interviews → highly relevant target interviews → difficult/stretch interviews → foreign opportunities → research labs / elite opportunities**

The early interviews can be companies/roles I don't actually want, but they are valuable as **confidence builders and reality checks**.

The core loop is:

**Interview → learn where I'm actually weak → improve → take a harder/more relevant interview → repeat**

### Important concepts

An opportunity should have things like:

- how much I want the job
- how useful the interview would be as practice
- estimated difficulty
- relevance to my career target
- how costly it would be to "waste" the opportunity
- where it sits in the progressive sequence

For example:

> "I don't really want this company, but this is a good low-stakes interview for me right now."

versus:

> "I really want this role. I should probably protect this opportunity until I've done a few more interviews."

The system should help me decide **which opportunities to use now vs later**, rather than simply ranking jobs.

### After every interview

Career OS should capture:

- what happened
- whether I passed/failed
- what rounds/topics were involved
- what I did poorly at
- what surprised me
- what I learned
- how confident I felt before vs after

That information should feed back into my career/interview readiness.

### UX

I want a simple view where I can see something like:

**Interview Progression**

`Practice → Low Stakes → Moderate → Target → Stretch → Foreign → Labs`

And underneath it:

- opportunities available at each stage
- opportunities I'm currently preparing for
- which opportunities I should probably take now
- which ones I should protect for later
- recent interview lessons
- my current biggest interview weakness

Do NOT over-engineer this.

### Implementation approach

1. First inspect the existing codebase and identify the smallest natural way to add this.
2. Reuse existing Career OS entities, services, components, and patterns wherever possible.
3. Do not create a giant new architecture just for this feature.
4. Build the smallest useful MVP end-to-end.
5. Keep the progression logic understandable and editable rather than building a complicated scoring/ML system.
6. Make sure I can manually override the system's recommendation.

### Implementation Summary

- **Reused Components**:
  - `src.models.Storage`: Reused strict RFC 4180 CSV serialization, auto-created `data/interviews.csv`, and unified prefixed IDs (`int_001`).
  - `Opportunity` Entity: Enriched with progression metadata (`progression_stage`, `desire`, `practice_value`, `stakes`, `progression_action`).
  - `CareerPrioritizer`: Injected `## 🎯 INTERVIEW PROGRESSION` into `outputs/daily_brief.md`, surfacing readiness, Take Now, Protect for Later, recent lessons, and weaknesses.
  - `src.runner`: Added `--agent progression`, `--agent log-interview`, and `--agent set-progression`.
- **New Components**:
  - `InterviewLog` dataclass (`src/models.py`) & `data/interviews.csv`.
  - `InterviewProgressionManager` (`src/progression.py`): Encapsulates progression ladder stages, readiness level calculation, and rule-based Take Now vs Protect for Later decisions.
